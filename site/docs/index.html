Overview#

AgentFleet installs 19 native Claude Code subagents — called lanes — under ~/.claude/agents/fleet-*.md and maps each lane to whatever models your provider offers: a Claude subscription, an Anthropic API key, or any Anthropic-compatible gateway. Lane names describe a role, never a model, so the same setup survives provider changes.

The moving parts:

  • Lanes — generated subagent files, one per role. Read-only lanes receive no Bash, Edit, or Write tools. All lanes run in the background with omitClaudeMd: true and cannot spawn nested agents; writable lanes are instructed never to commit, push, or take outward-facing actions.
  • Tier ranking at startup — a reconcile step compares your live provider models against each lane's required capability tier and assigns the best fit, spreading models across lanes and keeping assignments stable between sessions.
  • Hooks — a routing hook (UserPromptSubmit), a startup model-sync hook, a context-budget hook, and a privacy-safe status line, all installed under ~/.claude/.
  • Profiles — named provider configurations you can switch between without reinstalling. The native profile uses your Claude login; gateway profiles store tokens in mode-0600 files.
  • Safety — every apply operation takes a backup first; agentfleet rollback restores the previous state. Uninstall removes only files and settings owned by this bundle.

AgentFleet is for teams and individuals who use Claude Code daily and want a consistent, well-structured agent fleet that adapts to their provider without manual configuration. Everything lives under your home directory; no root or admin access is required.

Requirements#

  • Claude Code
  • Python 3.10 or later
  • Node.js 18 or later (required for agent generation and gateway model discovery)

Supported platforms: macOS, Linux, and Windows. No root or admin access is required.

Install#

The download script fetches releases/latest.json, downloads the pinned release archive, verifies its SHA-256, extracts it to ~/.local/share/agentfleet/releases/<version> (Windows: %LOCALAPPDATA%\AgentFleet\releases\<version>), then runs bin/install.py.

macOS / Linux

curl -fsSL https://agentfleet.wecansync.com/install.sh | sh

Windows (PowerShell)

irm https://agentfleet.wecansync.com/install.ps1 | iex

From a clone, ./install.sh (or install.ps1 / install.cmd) does the same.

Note

Pin a version with AGENTFLEET_VERSION=2.0.3. Override the host with AGENTFLEET_BASE_URL (https only; http is accepted only for localhost).

curl -fsSL https://agentfleet.wecansync.com/install.sh | AGENTFLEET_VERSION=2.0.3 sh

What the installer does#

  1. Fetch the release manifest

    Downloads releases/latest.json from the configured host.

  2. Download the pinned archive

    Fetches the release archive named in the manifest, or the version pinned by AGENTFLEET_VERSION.

  3. Verify the checksum

    Confirms the archive's SHA-256 before extracting anything.

  4. Extract under your home directory

    Unpacks to ~/.local/share/agentfleet/releases/<version> (or the Windows equivalent). No root or admin access is required.

  5. Run the installer

    Runs bin/install.py, which writes the managed files described in What gets installed.

First-run wizard#

On a fresh interactive install, the wizard asks how Claude Code should reach its models. There are three choices:

  1. Claude subscription (default)

    Uses Claude Code's own login. Lanes are mapped to the opus, sonnet, and haiku aliases. No catalog discovery is needed.

  2. Anthropic API key

    Reads ANTHROPIC_API_KEY from the environment. Lanes use first-party model IDs directly.

  3. Custom gateway

    Asks for an https URL and the name of the environment variable that holds the token (default: AGENTFLEET_GATEWAY_TOKEN). If that variable is unset, the wizard prompts for the token with hidden input. It then calls GET /v1/models to discover models, shows each model's assigned tier, and offers to adjust tier labels before writing anything.

Updates never run the wizard. They keep the installed profile and skip directly to reconciliation.

--no-wizard

Never prompt; keep or infer the provider from the current install.

Lanes#

Each lane is a native Claude Code subagent generated from ~/.claude/fleet.json. All lanes run in the background with omitClaudeMd: true. No lane has the Agent tool, so none can spawn nested agents. The main agent owns integration and every outward-facing action.

Read-only lanes have no Bash, Edit, or Write tools, so they cannot change files, commit, or push. Writable lanes have those tools; their instructions forbid committing, pushing, deploying, or publishing, but that rule lives in the prompt, not in the tool list.

Planning and architecture. Read-only design, multi-file approach comparisons. Tier: deep.

General implementation: building features, fixing bugs, refactoring, migrations. Tier: balanced.

fleet-reviewRead-only

Code review: defect review, correctness checking, regression auditing. Tier: deep.

fleet-testsWritable

Test writing, test execution, investigating flaky suites. Tier: balanced.

fleet-uiWritable

UI and frontend work: components, layout, styling, accessibility, frontend polish. Tier: balanced.

fleet-docsWritable

Documentation: READMEs, developer guides, API docs, runbooks, changelogs. Tier: balanced.

fleet-security-reviewRead-only

Security review: auth, secrets, validation, trust boundaries, injection, credentials. Tier: deep.

Variant lanes#

Variant names describe a capability, never a model, so they survive provider changes.

fleet-plan-altRead-only

Second planning opinion from an independent model. Use when cross-checking a plan or when the primary plan lane must be avoided. Tier: deep.

fleet-implement-altWritable

Implementation on an independent model. Use for an independent attempt or when the primary implement lane has failed twice. Tier: balanced.

fleet-implement-fastWritable

Low-latency implementation for small, well-specified edits where speed matters more than depth. Tier: fast.

fleet-implement-deepWritable

Reasoning-capable implementation for multi-file changes, tricky algorithms, or migrations that need deep reasoning. Tier: deep.

fleet-implement-cheapWritable

Budget or free-tier implementation: mechanical edits, boilerplate, and large repetitive changes. Tier: cheap.

fleet-review-altRead-only

Independent second reviewer on a different model. Use for risky changes that deserve two reviews. Tier: deep.

fleet-review-deepRead-only

Frontier reviewer for the hardest reviews: security boundaries, installer/migration/concurrency paths, data-loss risk, or conflicting primary findings. Tier: deep.

Tiers#

Every discovered model gets a capability tier: cheap, fast, balanced, or deep. The tier is determined in priority order:

  1. Explicit label

    A label you set with claude-fleet-setup --tier MODEL=TIER always wins.

  2. Keywords in the model ID

    cheap: free, cheap, budget, auto
    fast: haiku, flash, mini, lite, nano, fast, small, instant
    deep: opus, pro, max, ultra, large, sol, astra, o1, o3, reasoner

  3. Keywords in the catalog description

    cheap: "free", "cheapest", "budget", "low cost", "low-cost"
    fast: "fastest", "low latency", "low-latency", "quick", "fast"
    deep: "strongest", "deep reasoning", "deeper reasoning", "frontier", "most capable"

  4. Default

    balanced when no keyword matches.

Catalogs report context size but not price or speed — that is why explicit labels exist for models whose names do not signal their tier.

Ranking rules#

At startup the reconcile step ranks all live models for each lane. Tier fit dominates the score. Among equal-tier candidates:

  • Models that support reasoning rank higher for read-only lanes and deep-tier lanes.
  • Models with at least 800K context rank higher. Long-context lanes (fleet-research-codebase) give a larger bonus to 800K+ models.
  • The current model receives a stability bonus, so a settled fleet does not reshuffle on every startup.
  • Models already serving as another lane's primary lose a small penalty, spreading equally capable models across lanes.
  • An -alt lane never shares its sibling's model. This is a hard rule: the sibling's model receives a very large penalty, so the alt picks a different model unless nothing else is live.

The next-best ranked models become each lane's fallbacks (at most 3 entries per lane), so every live model can serve somewhere regardless of how many lanes exist.

Tuning#

Use claude-fleet-setup to pin models to lanes, keep models out of the fleet, label model tiers, and re-rank the fleet.

Pinning a lane to a model#

# Pin fleet-implement to a specific model:
claude-fleet-setup --prefer fleet-implement=my-model-id

# Pin with an ordered fallback list:
claude-fleet-setup --prefer fleet-implement=my-primary-model,my-fallback-model

# Clear the pin so the lane returns to tier ranking:
claude-fleet-setup --prefer fleet-implement=

A pinned lane uses your models in your order, and any remaining fallback slots are filled by tier ranking, so a lane pinned to one model still has somewhere to go if that model is unavailable.

Note

On a Claude subscription only opus, sonnet, and haiku can be used as preferred model values.

Keeping a model out of the fleet#

# Never assign this model to any lane, as a primary or a fallback:
claude-fleet-setup --exclude my-model-id

# Allow it again:
claude-fleet-setup --include my-model-id

An excluded model stays in Claude Code's /model picker; it just never serves a lane. Excluding a model also removes it from any lane pins, and pinning an excluded model is refused until you include it again. Exclusions are stored as excludedModels in ~/.claude/fleet.json and survive updates.

Labelling a model's tier#

# Label a model as fast:
claude-fleet-setup --tier my-model-id=fast

# Clear a label (returns to keyword inference):
claude-fleet-setup --tier my-model-id=

Re-ranking now#

claude-fleet-setup --reconcile

Fetches live provider models, runs the full ranking pass, and regenerates all agent files. Run this after changing tier labels or after a provider catalog update.

Tip

Run /fleet-setup inside Claude Code for an interactive wizard that walks you through all tuning options, including assigning models to lanes one by one, profile switching, tier labels, and agent curation.

Custom lanes#

Add a custom lane by editing ~/.claude/fleet.json directly. The lane name must start with fleet-. Required fields:

FieldValue
implementerMust be "claude".
tierOne of "cheap", "fast", "balanced", or "deep".
effortOne of "medium", "high", or "xhigh".
readOnlytrue to deny Bash/Edit/Write tools; omit or false for a writable lane.
descriptionPlain-text description of what the lane does. Used in the agent's brief.

After editing fleet.json, run reconcile to generate the agent file and assign the model:

claude-fleet-setup --reconcile

Custom lanes survive updates and profile switches. A lane marked readOnly: true always receives read-only tools regardless of any other configuration.

Tip

The /fleet-setup wizard in Claude Code can create a custom lane interactively — it asks for the name, description, read-only setting, and tier, then runs reconcile for you.

Profiles#

Profiles let you switch providers without reinstalling, and you can keep as many as you like: one per gateway, plus native for your Claude login. Lane names stay the same; only the models behind them change.

agentfleet profiles

List saved profiles with each one's provider policy. The active one is marked with an asterisk.

agentfleet use native

Switch to your Claude subscription or API key login.

agentfleet use <name>

Switch to a saved gateway profile.

agentfleet save <name>

Name and save the current configuration as a profile.

agentfleet add <name> --gateway-url URL

Add another gateway as a profile without reinstalling. See Adding a provider.

agentfleet remove <name> [--yes]

Delete a saved profile and its token. The active profile and native cannot be removed.

Switching first saves the current setup, so switching back restores it exactly. Restart Claude Code after switching profiles.

Each profile keeps its own provider policy (the model families it approves and the gateway's naming conventions), lane pins, excluded models, and tier labels. A pin or exclusion you set on one provider does not follow you to another, whose models have different names.

Adding a provider#

agentfleet add saves a new gateway profile without reinstalling:

export OPENROUTER_TOKEN=...   # or leave --token-env out to be prompted
agentfleet add openrouter --gateway-url https://openrouter.ai/api --token-env OPENROUTER_TOKEN
agentfleet use openrouter     # or pass --use to add

It lists the gateway's models first, and saves nothing if the token is rejected or no model is available. Every lane is assigned one of that gateway's models, under a generic policy that approves all of its models. The token is read from the named environment variable, or typed at a hidden prompt when you leave --token-env out; no flag takes the token itself, so it never lands in your shell history. --force replaces a saved profile of the same name. http:// is accepted only for localhost, with --allow-insecure-http.

The gateway must accept Anthropic Messages requests and list its models at /v1/models.

Provider--gateway-urlNotes
OpenRouterhttps://openrouter.ai/apiNamespaced model ids (anthropic/claude-sonnet-4.5); the model list includes context sizes.
LiteLLM proxyyour proxy, e.g. http://localhost:4000Its model list has no context sizes.
Vercel AI Gatewayhttps://ai-gateway.vercel.sh/claude-codeClaude Code support is documented; the model list endpoint is not, so add may be unable to list models.
OpenCode Zenhttps://opencode.ai/zenClaude models only on its Anthropic endpoint; the base URL is not documented.

Tip

Re-running the installer with a different --gateway-url also switches providers, but it cannot keep the old setup: it uses the policy and choices of a saved profile for that endpoint if there is one, and otherwise the generic policy without the old provider's pins and exclusions. Prefer agentfleet add.

Where profiles are stored#

  • Profiles: ~/.claude/agentfleet/profiles/
  • Gateway tokens: ~/.claude/agentfleet/secrets/<name>.token (mode 0600, directory mode 0700)

Switching to native#

When you switch to native, AgentFleet removes ANTHROPIC_BASE_URL, ANTHROPIC_AUTH_TOKEN, and the ANTHROPIC_DEFAULT_*_MODEL environment overrides from settings, then maps lanes to the opus, sonnet, and haiku aliases.

Gateway profiles set ANTHROPIC_API_KEY to an empty string in settings.json, because Claude Code would otherwise send an API key exported in your shell instead of the gateway token. Switching to native removes it. A non-empty key already in settings.json is yours and is left alone, with a warning.

Note

The name native is reserved and cannot be used as a custom profile name.

fleet-setup#

Type /fleet-setup inside Claude Code to run the interactive setup wizard. It audits the live state of your fleet, then walks through five phases:

  1. Phase 1: Silent audit

    Runs claude-fleet-setup --audit --json and agentfleet profiles. Collects: active profile, live model count and tiers, settings health (stale model / advisorModel / ANTHROPIC_*_MODEL values, compaction window), hook health, fleet lane count, and non-fleet agents and skills with their token cost.

  2. Phase 2: Status and wizard questions

    Prints a 4–6 line status summary drawn entirely from live audit data, then asks only the questions that apply:

    • Step 1 — Stale settings (only if found): for each stale key, offers up to three live models of the matching tier, plus "Keep unchanged". Applies with claude-fleet-setup --fix-settings.
    • Step 2 — Provider profile: stay on the current profile, switch to a saved one or native, add a provider, or remove one. To add a provider, the wizard asks for a name, the gateway URL, and the name of the environment variable that holds the token, then runs agentfleet add; if you would rather type the token, it gives you the command to run in a separate terminal. It never asks for a token in the chat. Step 3 choices apply to the active profile.
    • Step 3 — Fleet tuning: auto-rank all lanes (recommended), assign models to lanes, fix model tier labels, or keep current assignments.
    • Step 4 — Agent curation (only if non-fleet agents exist): keep all, archive entire domains not relevant to your work (e.g. game_dev, niche_ops), or archive one category. Fleet lanes are never archived.
    • Step 5 — Skills and new agents: archive legacy delegate wrappers, create a custom lane, or do nothing.

  3. Phase 3: Apply, verify, summarize

    Runs the chosen commands, then verifies with two required gates:

    1. Gate 1

      claude-fleet-sync --check must pass.

    2. Gate 2

      claude-agents-doctor --check must pass.

    If either gate fails, the wizard shows the error and fixes the cause before finishing. It ends with at most 4 lines summarizing what changed, what was left alone, and whether both gates passed.

Assigning models to lanes#

Choose Assign models to lanes in Step 3 to build the fleet together with the wizard:

  1. Suggested fleet

    The wizard reads every live model's description, tier, reasoning support, and context size from your provider's model list, and proposes a model for each lane. It keeps -alt lanes independent and spreads strong models across lanes.

  2. Approve or go model by model

    Apply the suggestion as is, or walk through the models one at a time (up to four per question).

  3. Pick lanes per model

    For each model the wizard recommends the lanes that fit it best. Pick one or more lanes, Skip it (auto-ranking decides where it helps), or choose Don't use this model to exclude it.

  4. Confirm

    Review the resulting fleet, then apply it or start over. The wizard pins only the lanes whose choice differs from auto-ranking, so the rest keep adapting as your provider's models change.

Note

The wizard never shows raw JSON, never edits files by hand, and always writes through claude-fleet-setup and agentfleet to hold the shared lock and keep both fleet mirrors in sync.

What gets installed#

Everything lives under your home directory. No root or admin access is required.

Fleet agents#

  • ~/.claude/agents/fleet-*.md — one generated agent file per lane, each with an optional fallback model chain (at most three entries, used only for provider unavailability or overload).

Settings#

  • ~/.claude/settings.json — merged settings. Unrelated permissions, hooks, plugins, and environment values are preserved. Mode 0600 (may contain a gateway token).

Hooks and scripts#

  • ~/.claude/route-to-fleet.py — UserPromptSubmit routing hook.
  • ~/.claude/subagent-statusline.py — native subagent status rendering.
  • ~/.claude/sync-provider-models.mjs — startup hook for gateway model discovery and fleet reconciliation.
  • ~/.claude/sync-model-context.py — PostModelSwitch / SessionStart hook that reads the active model's context length and keeps autoCompactWindow and CLAUDE_CODE_AUTO_COMPACT_WINDOW paired and bounded. Fail-open.
  • ~/.claude/provider_catalog.py and ~/.claude/fleet-reconcile.py — provider identity, cache, and reconciliation helpers used by startup hooks.
  • ~/.claude/fleet-model-drift.py — fail-open drift detector that writes a mode-0600 proposal and emits bounded startup context.

CLI wrappers#

  • ~/.local/bin/agentfleet, claude-fleet-setup, claude-fleet-sync, claude-agents-doctor (POSIX), or equivalent wrappers on Windows.
  • ~/.claude/claude-fleet-setup.py — the setup and reconfigure tool. Prompts only when running in a TTY; hooks never invoke it interactively.

Fleet map, policy, and manifest#

  • ~/.claude/fleet.json — the canonical fleet map. A legacy mirror is kept in sync at ~/.config/delegate-skills/config.json.
  • ~/.config/delegate-skills/provider-policy.json — provider policy. Generic (one catch-all family) on a fresh install; an existing install keeps its provider-specific families and aliases on update, unless --gateway-url names a different gateway. agentfleet use swaps in each profile's own policy.
  • ~/.claude/CLAUDE.md — the global delegation policy. AgentFleet manages this file and rewrites it on update. Keep your own instructions in ~/.claude/rules/*.md, which Claude Code loads in every session and AgentFleet never touches.
  • ~/.claude/.claude-agents-config-manifest.json — installed-tree verification data. The doctor uses this and does not require the source clone.
Note

Machine-local marketplace source paths are not copied (they are not portable). Remote marketplace entries, enabled plugin selections, permissions, and model picker descriptions are preserved. agent-brain hooks are guarded with command -v and are inert when that optional tool is absent.

Context compaction#

The context-budget hook (sync-model-context.py) runs at SessionStart and PostModelSwitch. It reads the active model's reported context_length, applies 90% headroom, and writes matching values to both CLAUDE_CODE_MAX_CONTEXT_TOKENS (in env) and autoCompactWindow in settings.json.

For example, a model reporting a 272K context window produces a budget of 244,800 tokens. An existing lower user budget is never inflated — the hook only adjusts when its own computed value is lower than what is currently set.

These are startup-only settings. The hook emits a restart notice when they change, because Claude Code reads them at launch. The hook is fail-open: any error is silently ignored and does not block a session.

Privacy#

The routing hook writes only to a mode-0600 JSONL log at ~/.claude/routing-log.jsonl.

What is stored#

Entry typeFields stored
Routed promptLane, reason, timestamp, character count. Never the prompt text.
No-match entryLane, reason, timestamp, character count, plus up to a 160-character excerpt of the prompt — with any credential-shaped values redacted before storage.

Retention and rotation#

  • Prompt text excerpts (no-match entries only) are removed after 14 days.
  • All entries are removed after 90 days.
  • Purging runs at most once per day.
  • The log rotates at 2,000,000 bytes.

The hook is fail-open: a logging failure does not block a prompt. The doctor checks these retention and redaction values in both the packaged and installed hook.

The automatic update check makes at most one request a day to https://agentfleet.wecansync.com/releases/latest.json, identified only by the user agent agentfleet/<version>; it sends nothing about your projects, prompts, or provider. Turn it off with agentfleet auto-update off.

Safety#

Backups before every apply

All managed files are copied to a mode-0700 snapshot under ~/.claude/backups/claude-agents-config/ before any write. The backup is kept until you remove it.

Rollback

agentfleet rollback (or python3 bin/install.py --rollback --apply from a clone) restores the newest pre-change snapshot. agentfleet rollback --backup DIR restores a named one.

Idempotent

Repeated installs produce the same configuration and do not generate duplicate hooks or agents.

Non-destructive uninstall

Uninstall removes only files and hook entries owned by this bundle. Unrelated top-level settings and plugin selections are not touched.

No accidental overwrites

Existing files without the bundle's ownership marker are never overwritten without --force-owned. When conflicts are found, they are listed and the install stops rather than overwriting silently.

Credential safety

The bundle scanner checks for credential-shaped literals before installation. The gateway token is the only secret normally needed; keep it in a protected environment variable, not in version control, shell history, or logs.

Settings ownership

Defaults that a later release stops shipping are taken back on update only if you never changed them. If you edited a value, it is treated as user-owned and preserved.

Upgrading#

To upgrade to the latest release:

agentfleet update
Warning

On versions 2.0.0 and 2.0.1, agentfleet update fails with HTTP 403 because Cloudflare blocks the default Python urllib user agent. This was fixed in 2.0.2. If you are on 2.0.0 or 2.0.1, run the install one-liner once to update past the broken version:

curl -fsSL https://agentfleet.wecansync.com/install.sh | sh

Automatic updates#

From 2.0.4 on, AgentFleet keeps itself up to date. Each time Claude Code starts, a quick hook checks at most once a day whether a newer release exists:

  • A newer release with the same major version is installed in the background, with the same checksum verification, backup, and doctor gate as agentfleet update. New sessions use it, and the next session mentions it in one line.
  • A new major version is never installed automatically; you get a one-time notice to run agentfleet update.
  • The hook never delays startup, prints nothing when there is nothing to report, and is skipped for installs made from a git clone.
agentfleet auto-update status   # enabled?, versions, last result
agentfleet auto-update off      # stop automatic updates
agentfleet auto-update on       # turn them back on

AGENTFLEET_AUTO_UPDATE=0 also turns them off, for example in CI. The state lives in ~/.claude/agentfleet/auto-update.json and each run's output in ~/.claude/agentfleet/auto-update.log. Versions before 2.0.4 need one manual update to get the hook.

The installer migrates automatically. Lanes that encoded vendor model names in their names are renamed:

  • Per-lane model choices and explicit preferred lists
  • Custom lanes defined in fleet.json
  • Explicit tier labels
  • Saved profiles

Troubleshooting#

Commands not found after install#

The CLI wrappers are installed to ~/.local/bin/. If your shell does not include that directory in PATH, add it:

export PATH="$HOME/.local/bin:$PATH"

Add this line to your ~/.bashrc, ~/.zshrc, or equivalent to make it permanent.

Node.js not found#

Agent generation and gateway model discovery require Node.js 18 or later. Install it from nodejs.org and ensure node is on your PATH.

Gateway models are not refreshed at startup#

The startup hook reads the gateway URL and token from ANTHROPIC_BASE_URL and ANTHROPIC_AUTH_TOKEN in ~/.claude/settings.json, which the installer and agentfleet use write. It does not read your shell environment. If the gateway is unreachable, the hook uses the cached catalog; if either value is missing from settings.json, it skips discovery and every lane keeps its current model.

To restore the credentials, switch back to a saved gateway profile with agentfleet use <name>, add the gateway again with agentfleet add <name> --gateway-url URL --token-env VAR --use, or re-run the installer with the gateway flags:

# Set the token first, outside shell history.
curl -fsSL https://agentfleet.wecansync.com/install.sh | sh -s -- --provider gateway \
  --gateway-url https://gateway.example.com --gateway-token-env MY_GATEWAY_TOKEN

No approved models after pointing settings.json at another gateway#

Reconcile reports no live approved candidate or unapproved model family: the provider policy still describes the previous gateway's model families, so none of the new gateway's models are approved. This happens when settings.json is edited by hand to point at another gateway. Add the gateway as a profile instead; it gets a policy of its own:

agentfleet add <name> --gateway-url https://gateway.example.com --token-env MY_GATEWAY_TOKEN --use

"another fleet writer is busy"#

The error message another fleet writer (installer or startup hook) is busy; try again in a moment means the installer, a startup hook, or another agentfleet command is holding the write lock. Wait a few seconds and retry. If the lock is stale (the owning process has exited), it will be released automatically.

Doctor: "static lane has write or nested-agent tools"#

A read-only lane's generated agent file contains Bash, Edit, Write, or Agent in its tool list. Re-run reconcile to regenerate the agent correctly:

claude-fleet-setup --reconcile

Doctor: "checksum mismatch"#

An installed file no longer matches its recorded checksum. If you edited the file intentionally, you can re-install to restore it. Otherwise run the full doctor to see all mismatches:

agentfleet doctor

Doctor: generated-agent count mismatch#

The number of agent files in ~/.claude/agents/ does not match the expected count from fleet.json. Run sync to regenerate missing files:

agentfleet sync

Changes not visible after profile switch#

Claude Code reads settings at launch. After switching profiles with agentfleet use, restart Claude Code to apply the new configuration.

agentfleet update fails with HTTP 403#

Versions 2.0.0 and 2.0.1 used the default urllib user agent, which Cloudflare rejected. This was fixed in 2.0.2. Run the install one-liner to update past the broken version:

curl -fsSL https://agentfleet.wecansync.com/install.sh | sh

FAQ#

Does AgentFleet work with a Claude subscription, or only with API keys?

It works with all three: a Claude subscription (uses the opus/sonnet/haiku aliases), an Anthropic API key, or any Anthropic-compatible gateway. The provider is chosen during the first-run wizard and can be changed at any time with agentfleet use.

Do lane names change when I switch providers?

No. Lane names describe roles, not models. fleet-implement is always the general implementation lane regardless of which model is behind it. Only the model changes when you switch profiles.

Can I use a lane that is not in the default set?

Yes. Add an entry to ~/.claude/fleet.json with implementer: "claude", a tier, effort, optional readOnly, and a description. Then run claude-fleet-setup --reconcile to generate the agent file and assign a model. Custom lanes survive updates and profile switches.

What happens if no model matches a lane's tier?

The ranking algorithm uses tier distance: if no model exactly matches the required tier, the nearest available tier is used. A fast model is preferred over nothing for a cheap-tier lane when no cheap model is available. Fallback chains (up to 3 entries) cover provider unavailability or overload.

Will AgentFleet overwrite my existing Claude Code settings?

No. The installer merges into settings.json: unrelated permissions, hooks, plugins, and environment values are preserved. Existing files without the bundle's ownership marker are never overwritten without --force-owned. Every apply runs a backup first.

Where should I put my own Claude Code instructions?

Put them in ~/.claude/rules/*.md. Claude Code loads all files in that directory in every session. AgentFleet manages ~/.claude/CLAUDE.md and rewrites it on update, so personal instructions placed there will be lost.

How do I revert an update that broke something?

Run agentfleet rollback. Every apply operation takes a backup of the managed files first, stored in ~/.claude/backups/claude-agents-config/. The rollback restores the newest backup. Use --backup DIR to restore a specific named snapshot.

Is root or admin access required?

No. Everything is installed under your home directory. The only directories created are under ~/.claude/, ~/.config/, and ~/.local/.

Does AgentFleet send prompt data anywhere?

No. The routing hook writes only to a local mode-0600 log file. Routed entries contain the lane name, reason code, timestamp, and character count — never the prompt text. No-match entries keep a brief excerpt (max 160 characters, credentials redacted) that is purged after 14 days.

Is AgentFleet affiliated with Anthropic?

No. AgentFleet is an independent open-source project by WeCanSync, released under the MIT license. Claude and Claude Code are trademarks of Anthropic.

Development#

Running tests#

python3 -m unittest discover tests

Updating the manifest#

After editing any bundle file, update the manifest. The installer refuses a bundle whose manifest checksums do not match the actual files:

python3 packaging/update-manifest.py

Building a release#

# Build a reproducible release from a git commit:
python3 packaging/build-release.py --ref <commit>
# Produces:
#   dist/releases/<version>/agentfleet-<version>.tar.gz
#   dist/releases/<version>/agentfleet-<version>.zip
#   dist/releases/<version>/SHA256SUMS
#   dist/releases/latest.json

Deploying#

export AGENTFLEET_DEPLOY_HOST=user@server
sh packaging/deploy.sh --dry-run   # list every change and deletion first
sh packaging/deploy.sh             # upload site/, then archives, then latest.json

deploy.sh mirrors site/ with rsync --delete and only syncs into a web root that is empty or already carries the .agentfleet-docroot marker from an earlier deploy. Published release archives are never deleted.
